# v2 任务层过度触及底层细节且架构方向偏离需求

## 基本信息

- **严重级别**：P2
- **发现时间**：2026-01-24
- **修复时间**：2026-01-24

## 事故概述

在本次对话中，最初的重构方案偏离用户约束，提出了跨 v1/v2 的共享层设计，并在实现阶段仅做轻量封装，未达到“任务层不再操作底层细节”的目标，导致用户指出“这不叫简化与重构”。同时，任务层继续直接调用底层 `template_matcher`/`adb`/`ocr` 的细节，未满足“应抽象并在任务中仅调用高层函数”的要求。

## 原因分析

### 根本原因

1. **需求理解偏差**：未严格遵守“仅 v2、不要涉及 v1”的硬性约束，最初计划误包含 v1/v2 共享层。
2. **抽象层次不足**：实现只做轻量封装，没有将模板匹配、滑动重试、循环切换等操作下沉到抽象层，任务层仍直接触及底层细节。
3. **反馈收敛不及时**：用户明确指出“任务不应操作底层细节”，但初次执行仍未达到预期抽象程度。

### 引入问题的 Commits（如适用）

- N/A（需求偏差与实现不足发生在对话规划与初次修改中，非单一 commit 引入）

## 复现步骤

1. 用户明确提出“仅 v2、任务层不直接操作底层细节”的需求。
2. 方案中出现 v1/v2 共享层规划。
3. 实施阶段仅添加轻量封装，任务层仍直接操作模板匹配与截图。
4. 用户反馈“这不叫简化与重构”。

## 修复方案

### 修复描述

- 方案已纠正为**仅 v2**，并将模板匹配、滑动重试、循环切换下沉到 `gesture/page_detector`。
- 明确规则：**任务层不能直接调用底层接口**，若无抽象应补抽象，任务层只保留业务判断。
- 将 `claim_gifts/claim_rewards` 的主页检测流程下沉到 `page_detector` 统一入口，减少 `adb.screenshot` 与 `template_matcher` 的直接调用。

### 修复的 Commits（如适用）

- `90044a3` - refactor(v2): simplify open_pack flow

## 经验教训

### 做得好的地方

- 在用户反馈后能快速收敛方向并补充测试。
- 通过 `gesture/page_detector` 抽象收敛了 open_pack 的重复流程。

### 需要改进的地方

- 规划阶段必须严格遵守“仅 v2”的硬性约束。
- 当需求强调“抽象/封装”时，实施应优先完成“任务层不触底层”这一目标，而不是局部美化。

## 预防措施

1. **约束清单前置**：在 plan 中明确列出“禁止涉及 v1”的硬性约束，并自检后再进入实现。
2. **抽象准入门槛**：若任务层出现 `template_matcher`/`adb.screenshot`/`ocr_engine`，视为违例，必须先抽象再继续。
3. **实现验收规则**：提交前检查任务层是否只包含业务判断，而非底层操作。
