## 1. 全局性 UI/UX 问题

### 1.1 交互反馈 (User Feedback)
- **问题**: 代码中使用了原生的 `alert()` (在 `plans.js` 中) 来显示错误或提示。这种体验非常原始，且会阻塞 UI 线程。
- **建议**: 统一使用现有的 `showToast()` 函数或自定义模态框 (Modal) 来替代所有 `alert()`，提供非阻塞的、视觉一致的反馈。

### 1.2 无障碍性 (Accessibility)
- **问题**: `main.css` 中存在全局 `outline: none;` (第231行)，且未发现明显的 `:focus-visible` 替代样式。这导致键盘导航用户无法感知当前聚焦的元素。
- **问题**: 多个链接使用 `href="javascript:void(0)"`，这对屏幕阅读器不友好。
- **建议**: 移除全局 `outline: none` 或为所有交互元素添加清晰的 `:focus-visible` 样式；将伪链接改为 `<button>` 元素。

### 1.3 加载状态 (Loading States)
- **问题**: 仅部分区域（如记录列表）有明确的 loading spinner。在执行保存、刷新等异步操作时，按钮缺乏反馈。
- **建议**: 在所有执行异步操作的按钮上添加 loading 状态（禁用按钮 + 显示转圈图标），防止用户重复点击提交。

## 2. 代码与架构问题 (影响维护性与性能)

### 2.1 JavaScript 污染全局命名空间
- **问题**: 大量模块 (`bootstrap.js`, `utils.js` 等) 直接将函数挂载到 `window` 对象上 (如 `window.showToast`, `window.openModal`) 以便 HTML 中的 `onclick` 调用。
- **建议**: 逐步迁移到 `addEventListener` 事件委托模式，保持全局环境清洁，避免命名冲突。

### 2.2 内联事件处理 (Inline Handlers)
- **问题**: HTML 模板中大量使用 `onclick="..."`。
- **建议**: 将事件处理逻辑与 HTML 结构分离，使用 `data-action` 属性在 JS 中统一绑定事件。

### 2.3 innerHTML 安全性
- **问题**: 多处使用 `innerHTML` 直接拼接字符串 (如 `filters.js`, `plans.js`)。
- **建议**: 虽然目前是内部工具，但为了防止潜在 XSS 和性能问题，建议使用 `document.createElement` 构建 DOM 或使用更安全的模板渲染方式。

## 3. 页面级具体问题

### 3.1 每日送卡页面 (`#daily-gift`)
- **日期选择器**: 目前是平铺的一排按钮，如果在移动端或日期较多时可能会换行导致布局杂乱。
  - **建议**: 优化为下拉选择或水平滚动条容器。
- **状态展示**: "成功/失败/等待中" 的统计数字比较单调。
  - **建议**: 增加颜色区分（绿/红/灰）或简单的进度条可视化。

### 3.2 开包记录页面 (`#records`)
- **卡片展示**: 网格视图下，如果卡片名字过长可能会破坏布局。
  - **建议**: 检查并优化卡片标题的 `truncate` (截断) 样式。
- **筛选器**: 筛选器区域在移动端可能占用过多屏幕空间。
  - **建议**: 增加“折叠/展开”功能。

### 3.3 拥有卡牌页面 (`#owned-cards`)
- **筛选逻辑**: 目前的筛选器逻辑较为复杂，使用了大量 checkbox。
  - **建议**: 优化为更现代的 Tag 选择器或多选下拉框。
- **列数切换**: "5, 6, 7" 列的切换按钮样式较简单。
  - **建议**: 改为更紧凑的 `Segmented Control` 样式。

### 3.4 任务计划页面 (`#plans`)
- **拖拽排序**: 现在的拖拽排序功能依赖于 JS，需要确保拖拽时的视觉反馈（如占位符、阴影）足够清晰。
- **空状态**: 当没有计划时，目前的提示可能不够显眼。
  - **建议**: 增加引导性的“新建计划”大按钮。

### 3.5 账号管理页面 (`#accounts`)
- **信息密度**: 列表项包含大量信息（ID、点数、沙漏、配置）。
  - **建议**: 优化排版，弱化次要信息（ID），高亮关键指标（点数、沙漏）或图标化。
- **复制功能**: 点击复制 Friend ID 的交互需要明确的反馈。
  - **建议**: 鼠标悬停时的 `cursor` 样式应确保是手型 (pointer)。

### 3.6 好友关系页面 (`#friendships`)
- **表格对齐**: 好友请求和关系记录是表格形式，需要确保各列（尤其是操作列）对齐，避免因内容长短不一导致的错位。
