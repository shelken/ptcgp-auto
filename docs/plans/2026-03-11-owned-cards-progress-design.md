# 拥有卡牌页未拥有展示与顶部进度设计

## 背景

拥有卡牌页当前只展示至少被一个账号拥有的卡牌，无法直接浏览未拥有卡牌。页面顶部也缺少进度概览，无法快速判断高稀有度收集进展。

## 目标

1. 在拥有卡牌页中展示未拥有卡牌，并通过蒙版与已拥有卡牌区分。
2. 保持列表点击逻辑不变，继续复用现有卡牌详情弹窗。
3. 新增顶部统计区，展示当前筛选结果数与固定的高稀有度全局进度。

## 交互设计

### 列表

- 页面支持展示未拥有卡牌。
- 未拥有卡牌继续使用原卡图，但叠加灰度与深色蒙版。
- 卡片点击结构不变，继续使用现有详情弹窗接口。
- 列表筛选与排序逻辑保持原有结构，仅扩大数据来源。

### 顶部统计

- `filtered_cards_count`：受当前列表筛选条件影响，表示当前筛选条件下的卡牌数量。
- `rarity_progress`：固定全局统计，不受任何列表筛选影响，只统计 `HIGH_RARITY_TARGETS`。
- 顶部统计区始终显示在列表顶部，刷新按钮同时刷新列表与统计。

## 数据口径

### 列表

- 从 `Card` 表起查，左连接按卡牌聚合后的 `AccountCard` 数据。
- 已拥有定义：聚合后的 `total_count > 0`
- 未拥有定义：聚合后的 `total_count = 0`
- 列表项需要额外提供 `ownership_state` 字段，值为 `owned` 或 `missing`

### 统计

- `filtered_cards_count` 使用与列表相同的筛选参数，统计当前结果数。
- `rarity_progress` 固定按 `HIGH_RARITY_TARGETS = ["RR", "AR", "SR", "SAR", "IM", "UR", "S", "SSR"]` 统计。
- `owned_count` 定义为：至少被一个账号拥有的卡种数。
- `total_count` 定义为：该稀有度下的总卡种数。

## 实现范围

- 仓储层：统一卡牌列表查询，支持返回已拥有与未拥有状态；新增顶部进度查询。
- 服务层：产出列表上下文与统计上下文。
- 路由层：新增顶部统计接口。
- 模板层：列表卡片增加未拥有状态样式；页面顶部增加统计区。
- 样式层：增加未拥有卡牌蒙版样式与统计条样式。
- 测试层：补充列表上下文、统计上下文与新接口测试。
