## 需求

### 基本

该任务类型 once，一般仅在web端管理员直接操作发起

能在 web 页面直接对某个friend id发起交换卡牌操作

前置hook：FriendPreHook（好友检查）

提醒：下方如果出现任务失败的描述，记住不是task instance的失败，而是request记录的失败，如果把task弄成失败，按照目前逻辑会一直重置失败任务，所以要问清楚

### web

#### 换卡入口

首先位置在 拥有卡牌 那里，点开某个卡牌后的modal。
需要改造这个modal，当前有不少问题，需要重新设计。

首先要有能够过滤账号的搜索框。
第二，左边的卡牌要小点，目前跟右边是对半分的，这不对。
第三，左边的卡牌，应该跟在「抽卡记录」的的卡牌展示逻辑一样，支持拖拽卡牌各角度查看。

然后是右边的账号列表，首先，在卡牌数量不为0的记录应该支持送卡点击，点击后，能够让我输入要交换的friendid，

需要让用户确认赠送。然后点击确认后，应该生成一条交换记录，status为sending，这里可以参考`AccountFriendRequest`的表设计，很相似。我们暂时命名`ExchangeCardRequest`

前置检查

必须先检查选择的账号是否有sending或者sended阶段的操作，如果有，不允许交换。每次一个账号只有一个request在运行（查询非completed/failed/canceled）

#### 管理记录

管理页面 的 左边栏 增加交换记录可以管理交换的所有记录

前面的request生成后，应该这里可以看到并管理

状态有好几个阶段，发送后 就是 sending，此时需要能够触发对应账号的对应任务。
当对应账号送出指定卡牌之后，状态变为 sended；管理端可以直接取消
如果中途被取消，如果是sending，直接变更记录canceled，
如果是sended状态，那么应该触发对应账号的任务，让其取消掉送出的卡牌后，然后变更为canceled，写上理由
如果因为各种原因失败了，状态变为failed，写上理由

然后是sended的处理，当sended之后，需要交换方接受，并等对方送出相同rarity等级的卡牌之后，我们这边点击接受才能完成整个交换卡牌流程。

因此，我们将在sended之后的某个时间范围内重新触发任务，检查当前对方是否也完成发送卡牌的操作，目前我们可以设计x分钟后重新检查对方是否发送了(参考下面更详细的描述）。

如果对方没有发送，我们直接取消本次交换，记为canceled，写上理由，也就是默认给x分钟窗口让对方接受。


### task（exchange_cards）

先读取其他task，参考相关写法和出现的同样的逻辑规则
可参考的task `send_card_daily` `fetch_account_info` `collect_account_cards`（筛选页面逻辑）

#### 前置条件

进来任务，此时需要做些前置判断

- 检查当前是sending还是sended，如果是sedning，走换卡流程，如果是sended，检查换卡状态
- 检查当前账号的交换点数，如果交换点数为0或者低于卡牌等级所需的交换点数，直接完成本次交换，request 状态 failed，记上理由

**交换点数映射规则**：
| 稀有度代码 | 图标 | 所需交换点数 | 备注 |
|-----------|------|-------------|------|
| C (Common) | 1◇ | 0 | - |
| U (Uncommon) | 2◇ | 0 | - |
| R (Rare) | 3◇ | 1200 | - |
| RR (Double Rare) | 4◇ | 5000 | - |
| AR (Art Rare) | 1☆ | 4000 | - |
| SR (Super Rare) | 2☆ | 25000 | - |
| SAR (Special Art Rare) | 2☆ | 25000 | - |
| S (Shiny) | 1✸ | 10000 | - |
| SSR (Shiny Super Rare) | 2✸ | 30000 | - |
| IM (Immersive Rare) | 3星 | ❌ 不可交换 | 游戏限制 |
| UR (Crown Rare) | 皇冠 | ❌ 不可交换 | 游戏限制 |

**注意**: 如果用户尝试选择 IM 或 UR 稀有度的卡牌进行交换，应在 Web 端前置拦截，不允许发起交换请求。
- 然后检查当前账号的将换卡牌的数量，必须大于等于1
- 14 天账号冷静期（和 `send_card_daily` `fetch_account_info` 任务中一样的逻辑），检查当前账号创建时间大于14天,否则无法换卡，小于14天 直接完成本次交换，request 状态 failed，记上理由
  - 参考实现：`src/ptcgp_auto_v2/utils/account_cooldown.py:is_account_past_days()`
  - 使用示例：`src/ptcgp_auto_v2/tasks/send_card_daily.py:231-233`
