## 新需求

现在，将实现完整流程来替换掉 @src/ptcgp_auto_v2/tasks/open_pack.py 中识别卡牌的行为（目前通过加载模板的方式）

我们目前应该会有的流程应该有：

首先在开包完成页面扫描卡牌的时候，调用新的扫描方法（直接重写），能够传进obb边框阈值、相似度阈值等参数，不过一般不用传（默认用常量定义的）

扫描后，返回一个列表，按照人类可读顺序从左到右，一直往下的顺序排，每个实体都是 最佳的那张 每个实体包含了最佳的card信息，方位信息，相似度信息

然后就是按原来的逻辑入库pack_card

然后就是scan的逻辑，大概就是，加载模型（模型应该提前加载，整个脚本启动时，而且要异步，因为我测试过，每次重新加载要等的时间是最长的）
使用yolo模型检测->通过裁剪图片、一系列处理->计算hash->查询数据库卡牌的hash进行匹配（这里需要优化，我们测试脚本中使用了json文件存储，我目前
想法是使用数据库来存储，但是我不知道如果要如何快速让hash值和数据库的进行快速匹配，这个地方你给方案，我来参考）
->取最佳卡牌，然后以此类推全部->返回所有检测的卡牌

这个流程中，

如何下载模型/管理模型？需要你重新思考。首先模型来源使用我上述说的repo，还有如果是mac，则加载coreml的，模型下载后放入data/models目录下
